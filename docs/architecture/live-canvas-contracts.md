# Live Canvas の購読・配置契約

対象は `apps/web`。全面的な再設計の提案ではなく現在の動作と改修時にも守る不変条件をまとめる。プロトコル上の識別子 `eventId` と画面上の同じ場所を表す `slotId` を混同しない。

## 最初に読む場所

- `app/page.tsx`: 標準画面の入口。`app/components/Home.tsx` が認証、リレー、スレッド構築、画面を接続する。
- `app/hooks/useNostrRelay.ts`: 接続・ノート・プロフィール・リアクション・キャッシュを組み合わせる。署名済みイベントの publish は1リレー以上の成功で成功とする。
- `app/hooks/useNostrConnection.ts`: pool の所有者。アカウント変更・ログアウト・unmountで破棄する。
- `app/hooks/useNostrNotes.ts`: kind:1/6 の購読、初期バッファ、リポストの取得、表示ノートの上限。
- `app/hooks/useNostrReactions.ts`: kind:7 の集計、重複排除、30秒ごとの対象更新。
- `app/hooks/useEventCache.ts`: 不変なイベントのIDキャッシュと進行中の取得共有。
- `app/components/LiveCanvasV2.tsx`: スコア再計算、下書き・投稿・スレッドの統合、holdの操作。
- `app/components/v2/scene.ts`: 配置状態とhold時の表示座標。`sceneMotion.ts` が移動と連鎖遅延を管理する。
- `app/components/v2/CanvasScene.tsx`: 高さ測定、focus・押下中の保持、native描画とDOM互換表示。
- `app/lib/layoutEngine.ts`: Reactに依存しない初期配置・挿入・reflow。

## 接続と購読の寿命

1. ログイン後に1つの `SimplePool` を作り、bootstrapリレーから最新の kind:10002 と kind:3 を取得する。
2. 接続先はbootstrapリレーと kind:10002 のリレーの和集合。指定リレーがなければbootstrapだけを使う。
3. フォローがあれば `loading` に進み、kind:1/6 の初期取得を始める。フォローは重複排除する。
4. フォローが空なら、全体タイムラインや暗黙の自己フォローへ広げず、空feedのまま `connected` にする。投稿のためpoolと接続先は残す。
5. ノートの初期EOSEと初期リポスト元取得が終わると `connected`。bootstrap自体の失敗は `error`。

`connected` は初期処理の完了を表す。全リレーが常時オンラインであることや、全履歴を取得したことの保証ではない。フォローなしで投稿したカードは現在の画面では楽観的に表示できるが、再読込後のfeedに自分の投稿を入れるには自分をフォローする必要がある。

pool・リレー・フォロー・アカウントなど購読条件が変わったら、ノートの購読を作り直す。前の購読を閉じ、表示ノート、リアクションの初期対象、追跡時刻をリセットする。古い購読からのイベント・EOSE・非同期取得の完了は、新しい画面や接続状態を変更してはいけない。

`subscribeMany` の再接続・複数リレー間の重複排除は `nostr-tools` が担当するが、hook側でも重複イベントと複数回のEOSEに耐える。cleanupで `close()` するだけでなく、既に配送されたコールバックも無効化する。

## ノートとリポスト

- 初期EOSEまでは kind:1 と kind:6 をバッファする。初期処理は購読1世代につき1回だけ。
- kind:1は `eventId` で重複排除し、スコア順で最大100件を残す。以後の追加時も上限を守る。REQの `limit:500` と表示上限は別物。
- kind:6は最後の有効な `e` タグを元ノートIDとして使う。元のkind:1をキャッシュ経由で取得する。元イベントが見つからない場合、リポストだけの空カードを作らない。
- 同じ元ノートのリポストは1枚に統合し、`created_at` がより新しいリポスト情報を採用する。同時刻は先に反映した情報を維持する。
- 初期リポスト取得を待っている間もライブノートを受け取る。取得結果は**現在のstateへの追加・更新**にし、await前の配列でstateを置き換えない。すでにある `slotId` と新しいリポスト情報を保持する。
- 初期取得後に実際のノートID一覧をリアクションhookへ通知する。初期feedが空でも、最初のライブノート／リポスト元ノートが届いたときに通知し直す。その後はリアクション側の定期購読で対象を更新する。
- ライブ到着した古いリポスト元ノートも、リアクションの取得開始時刻を決める最小 `created_at` に含める。

スコアは通常30分、本人のノートは1時間で半減する鮮度スコア。リポストはリポスト時刻を使う。LiveCanvasV2は10秒ごとに表示用スコアを再計算する。既存カードへのリポスト情報更新は表示側の再計算に反映される。スコア更新だけで既存カードを順位順に並べ直す仕様ではない。

## リアクション

初期対象IDがある場合だけkind:7購読を開始し、EOSE後は30秒ごとに古い購読を閉じ、現在のノートIDへ購読し直す。空の `#e` で無制限購読しない。

- 1購読世代のタイマーは1つだけ。重複EOSEやcleanup後のEOSEで増やさない。
- 初期バッファは現在の集計にマージする。送信成功後の楽観的リアクションを初期バッファで消さない。
- リアクションevent IDで重複排除する。リレーからのechoや再購読で数を増やさない。
- `since` は前回の切替基準時刻から10秒戻した値と、新着ノートの最小作成時刻の小さい方。定期処理後に新着時刻をリセットする。
- cleanupでタイマーと購読を閉じ、集計と重複排除集合を破棄する。

## キャッシュの契約

キャッシュは任意のFilterの検索結果全体ではなく`eventId → Event` の集合。公開イベントの本体はpoolが変わっても保持するが、進行中のREQを別poolへ流用しない。

- 64桁の完全IDを指定し、`limit` と `search` がない取得に限り、キャッシュ済みIDをREQから省略できる。
- キャッシュにあってもkind、author、タグ、時刻など、残りのFilterを満たさないイベントを返さない。
- 同一IDの重複指定は1件として扱う。未取得IDだけのREQを共有しても、各呼び出しのキャッシュ済み部分を混ぜない。
- 一般検索、prefix ID、`limit`／`search` 付きは、そのままリレーへ委譲する。キャッシュ内の一部のイベントを足して検索結果や上限を変えない。
- 取得中の共有キーはpool、Filter、検証済み接続先、maxWait。配列の並びが違う条件まで同一視する最適化はしない。
- 失敗・空結果は永続キャッシュしない。次の要求は再試行できる。
- 外部由来リレーヒントは `relayUrlPolicy.ts` で検証する。アカウント設定のリレーと、イベントに含まれる外部ヒントは別の信頼境界。

イベントの署名・REQに合うイベントの受信判定はpool層を利用する。キャッシュは未検証のJSONを受け入れるセキュリティ境界ではない。

## 配置とhold

エンジンの入力は一意なslotId、1以上の整数列数、有効な列、非負の座標と高さを前提とする。`Grid` は読み取り専用の入力で、公開操作は元MapやPlacementを変更しない。高さ未測定時は120px、縦gapは12px。

- 初期配置／列数変更: スコア順のカードを分配し、各列をスコア降順で上から積む。以前の列割当は引き継がない。
- 挿入: 各列のy=0の引力コストを比べて開始列を選ぶ。同点は左優先。新規カードが常に列0へ入るわけではない。
- 押し出し: 同列の直下、左右列の重なるカードを候補に、スコアと引力を使って移動先を選ぶ。holdの迂回先が循環したら現在列末尾へ退避し、必ず終了する。
- 高さ差の補正: 挿入後、holdの位置を保持し、それ以外を下方向へ移動して重なりを解消する。可動カード同士の列内順序は維持するが、holdカードの下へ回り込む場合がある。hold同士は入力時点で重ならないこと。
- reflow: 列割当と前回y順を維持し、現在の高さで積み直す。削除カードは除去し、未配置カードは追加しない。スコア変化でソートし直さない。
- 移動連鎖の順序は `chainOrder`。V2は新着を全て挿入し削除を反映した後、一度だけreflowして空隙を詰めた最終位置へ動かす。`sceneMotion.ts` は連鎖順を100ms倍、最大600msの遅延へ変換する。進行中の移動では速度と残りの待機時間を引き継ぐ。

V2の **grid（エンジン座標）** と **boxes（holdで固定した表示座標を含む）** は異なる。hold中は高さ変化などでエンジンがreflowしても現在の表示位置と幅を固定し、解除で追従する。列数変更でも表示の固定を維持するため、一時的な重なりや画面外への残留があり得る。`insertCard` の非重複保証を、全てのアニメーション途中やhold中の表示まで保証するものと解釈しない。

下書き→投稿済みカードは `publishedSlotMapRef` の同じslotIdを使い、測定高さや配置を引き継ぐ。eventIdが変わったことを理由にslotIdを作り直すと、新規挿入や不要なアニメーションになる。

## テストと改修手順

`apps/web` で実行する。

```sh
npm ci
npm run lint
npm test
npx tsc --noEmit --incremental false
npm run build
```

主な契約と回帰テストの対応は次のとおり。

| 契約 | 回帰テスト |
| --- | --- |
| 空フォロー、設定選択、pool破棄、古いbootstrapの無効化 | `hooks/__tests__/useNostrConnection.test.tsx` |
| EOSE、非同期リポスト競合、世代切替、初期空feed | `hooks/__tests__/useNostrNotes.test.tsx` |
| 重複EOSE、楽観的更新、タイマー、since、cleanup | `hooks/__tests__/useNostrReactions.test.tsx` |
| Filter整合、取得共有、pool変更、失敗再試行 | `hooks/__tests__/useEventCache.test.ts` |
| 実SimplePoolの再接続・複数リレー重複 | `hooks/__tests__/nostrPoolCompatibility.test.ts` |
| hold循環、可変高さ、入力不変性、連続挿入 | `lib/__tests__/layoutEngine.test.ts` |
| hold表示、解除・resize、同じslotId、削除＋挿入 | `components/v2/__tests__/scene.test.ts`、`components/v2/__tests__/sceneMotion.test.ts`、`components/v2/__tests__/CanvasScene.test.tsx` |

hookテストは制御可能なpoolと遅延Promiseで競合順序を固定する。ネットワーク速度や `sleep` に依存して再現しない。まず失敗テストを書き、関係する契約を読み、対象hook／純粋関数を小さく修正する。関数分割は契約を置く場所が必要になったときに行い、テスト追加と無関係な全面分割はしない。

ブラウザの実署名・投稿・再取得は[ローカルNIP-46 E2E手順](../testing/local-nip46-e2e.md)で補う。unitテストだけでは実署名器、DOMの測定、アニメーション、ログイン復元は保証しない。ブラウザの目視だけでは非同期競合を保証しない。公開リレー・実秘密鍵をテストに使用しない。

## 今回固定しない範囲

スレッド構築・プロフィール・カスタム絵文字など全hookの寿命を網羅した仕様ではない。hold表示の重なり解消、再接続状態の詳細表示、キャッシュ容量上限、同時フォロー更新の競合、全リレー失敗時のUXは別の設計課題として扱う。これらを変更するときは、その責務で再現テストと契約を追加する。
